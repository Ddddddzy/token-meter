# Token Meter / 60 秒产品宣传片制作计划

2026-10-10 · 任务栏与托盘开合关系修订

## 产品与事实边界

Token Meter 是 Windows x64 的本机 Agent token 用量统计工具。定位：给同时使用多个编程 Agent 的开发者一个低打扰的用量观察窗。

已核对 `D:/token-meter/README.md`、`panel.html`、`server.mjs`、`native/GlassEffects.cs` 和品牌 SVG。没有 package.json：产品后端只使用 Node 内置模块；本视频有独立 package.json，不改变产品依赖。

值得展示的能力：

1. 将支持来源的本地 Agent 日志汇总到一个托盘小窗；不需要配置 API Key。
2. 今日 / 7 天 / 30 天 / 全部范围，按 Agent 与模型观察分布和趋势。
3. Codex 用量展开为输入、缓存、输出、推理；缓存、推理是子集，不重复加总。
4. 小窗底边锚定开合、完整轮廓、可调不透明度与模糊度。
5. 源码在 GitHub，配置路径默认发现且可覆盖。

不能宣传：多设备统计（待开发）、ChatGPT 网页/手机用量、账户剩余额度、订阅账单、全模型精确计价、即时逐 token 流式统计。Cursor 必须标明估算；价格展示写“用量估价”，不得称“实际支出”。

## 视觉方向

沿用白底黑色三根递增信号条 Logo；视频舞台为石墨黑，产品界面保留实际浅色玻璃材质；唯一主要强调色使用产品蓝 `#5592ee`。不引入紫/青霓虹品牌。

按用户确认后的字体方向，中文使用宋体 (SimSun)，英文与数字使用 Times New Roman，包括 Token Meter 品牌文字。采用常见论文字体组合，不将其表述为所有论文统一的强制标准；使用渲染机器已安装字体，不分发系统字体二进制。大字、宽松行距、不堆满卖点。三根信号条贯穿 Logo、数据条和窗口轮廓的连续转场。镜头以平移、遮罩与尺度变化为主，微弱透视只用于产品完整 UI，不做夸张旋转或随机粒子。

3840×2160 母版、1920×1080 预览、30fps。以 1920 布局坐标设计，主要字幕至少 40px、关键内容安全区约 96px，任务栏阶段辅助演示标注距底边 110px。所有数字仅来自固定演示数据，不读取真实日志或桌面截图。凡展示用量数字，画面标注“演示数据”。底部任务栏为代码绘制的 Windows 11 风格演示，时钟为固定示例。

## 10 秒样片范围

本次只制作开场及痛点镜头的前半部分（第 0–299 帧），让用户先确定美术与节奏。不是 60 秒成片，也不应作为完整功能宣传片发布。

- 0–1.8s：三根竖条归位，线→标志，轻微镜头推进。
- 1.8–4.6s：品牌名与中文价值主张遮罩揭示，留出阅读时间。
- 4.6–6.2s：同一个 Logo 变小移到左上，排版与镜头连续重构。
- 6.2–8.1s：问题标题逐行进入，右侧示例卡片依序出现。
- 8.1–10s：蓝色计量线连接三份 usage 卡，标题与数据保持可读。

## 动画与实现约束

独立 React / TypeScript / Remotion 工程；帧驱动 `spring` / 插值 / SVG。全部轨迹纯函数，无 CSS animation/transition、setTimeout 或未固定随机数。源代码和依赖锁定版本；机器已安装的指定字体加载后再渲染。Logo 使用项目原有向量重建，不生成位图 Logo。

完整片使用 `music.mjs` 独立合成的轻电子 BGM 和柔和转场音效，无旁白，没有第三方歌曲或采样。原声为固定种子生成的 60 秒、48kHz 双声道 WAV，开场淡入、结尾淡出；成片编码 AAC。
